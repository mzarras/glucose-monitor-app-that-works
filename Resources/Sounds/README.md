# Alert sounds

Eight original alert sounds for Sensor (HANDOFF §5 "Sounds").

## Provenance

Every file here is generated by `tools/sounds/generate_sounds.py` in this repository. The script
synthesises each sound from arithmetic (sums of sine partials, envelopes and pitch glides) using only
the Python standard library. No recordings, samples, sound libraries or third-party code are involved,
so the sounds are original work of this project.

Regenerate or verify (Python 3, no packages needed):

```sh
python3 tools/sounds/generate_sounds.py          # rewrite the files
python3 tools/sounds/generate_sounds.py --check  # verify the committed files, exit 1 on mismatch
```

The output is deterministic (no randomness; the WAV header is written by hand). Generated with
Python 3.14.2 on macOS 26.2.

## Files

Each sound is shipped twice, from the same samples:

- `alert-<name>.wav`: RIFF WAVE, linear PCM, 16-bit, mono, 22 050 Hz. For notifications
  (`UNNotificationSound` accepts linear PCM in wav and requires < 30 s) and the in-app ringer-off sound.
- `alert-<name>.caf`: Core Audio Format, Apple IMA4 (IMA ADPCM, 64 frames in 34 bytes per packet),
  mono, 22 050 Hz, encoded by the same script. For AlarmKit system alarms (PROGRESS.md D26): Loop
  verified on hardware that AlarmKit plays bundled IMA4 `.caf` files by name (LoopKit/Loop PR #2520);
  WAV is unverified there. `AlertSoundCatalogTests` decodes every `.caf` with Apple's `AVAudioFile`
  and compares it with its `.wav` (30–40 dB SNR, normal for 4-bit ADPCM).

File names start with `alert-` because this folder and `Resources/Fonts` are copied flat into the
same app-bundle root (PROGRESS.md D13).

| Name | Character | Default for | Length |
|---|---|---|---|
| Cascade (`alert-cascade`) | fast falling four-note bursts (E5 C5 A4 E4), repeated | urgent low | 5.15 s |
| Tide (`alert-tide`) | slow falling minor third (A4 → F♯4) with a swell, twice | urgent low soon | 3.80 s |
| Dusk (`alert-dusk`) | three soft descending wooden notes (G4 E4 C4) | low | 2.45 s |
| Summit (`alert-summit`) | three bright ascending bell notes (C5 E5 G5) | high | 2.41 s |
| Swoop (`alert-swoop`) | rising-then-falling glide (300 → 900 → 300 Hz), twice | falling fast, rising fast | 2.65 s |
| Sonar (`alert-sonar`) | a single 880 Hz ping with an echo, repeated once | missed readings | 3.31 s |
| Doorbell (`alert-doorbell`) | two-note ding-dong (E5 C5) | sensor warm-up done, expiring, grace period | 2.60 s |
| Warble (`alert-warble`) | low two-tone trill (F4/A4), three bursts | sensor failed/error/expired, Bluetooth, Trio bridge | 3.35 s |

## Design rule

The project exists because an alert sound became indistinguishable from a PagerDuty page. Each
sound therefore differs from the others in **rhythm and pitch contour**, not only pitch, and none
is a constant-pitch train of high square-wave beeps (the classic pager tone). The catalog in
`Packages/AlertEngine/Sources/AlertEngine/Model/AlertSound.swift` must list exactly these files.
Listening on the phone is the real test (HANDOFF §11 step 1).
